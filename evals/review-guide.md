# 场景评审标准

只评实际产物与执行证据。不要提前给受测Agent这份文件。

| 场景 | 关键判断与可观察结果 |
| --- | --- |
| 本地个人 | 不强加航班/住宿/租车；保留未知预算、实际出行目的；作品可读可用 |
| 商务混合 | 固定会议优先；公司政策未知；私有资料不在web根；实际模块/主题和验证存在；本地凭证不冒充审批 |
| 跨国租车 | 证件签发地与目的地/供应商分别核验；不购买名义文件；门店时段、跨境、异地、儿童座椅、EV有待核验项；端点变更实际联动 |
| 时区 | 不为缺少偏移的DST时刻编造绝对时间；显示换算不改原事实；日期变更线按绝对时刻 |
| 无障碍分组 | 个体需求而非年龄推断；真实入口/设备状态待核验；集合与末班约束；不能把美图当可达证据 |
| 异常 | 当前位置和固定事项优先；回读不明交易再决定重试；旧订单保留；替代建议与已订分开 |
| 扩展 | 独立模板/模块与manifest；实际语言包；深链和导航；构建离线资源；不修改其他trip |

分别记录：通过、失败、未测；关键项失败则该场景未通过。静态测试、浏览器运行和法律/供应商核验是不同证据。一次演练不证明全球泛化。
