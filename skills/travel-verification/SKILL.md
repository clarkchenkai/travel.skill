# 旅行核验与验收

从用户的真实任务选择相关场景，不一次运行全世界的检查表。把“适用规则已找到”“个人条件满足”“供应商接受”“已完成办理/预订”分开记录。

## 核验方式

1. 先读取已确认事实、未知条件与授权。不要重新质疑用户已确认订单；需要补核验的具体条款单独列出。
2. 时效性信息查当前政府、运营商、供应商等直接来源，保留原名、直接URL、核验日期和适用人/地点/时间。未能核实就保留未知，不从别国、别种证件或车型套用。
3. 为关键要求写清“适用于谁 → 要做什么 → 在哪里办/找谁确认 → 材料与截止 → 完成证据”。程序性文本不等于已办理。
4. 网站验收必须检查来源、数据、实际界面和操作。先结构与逻辑，再真实浏览器任务；变更一个源字段后检查全部关联位置。
5. 已实现、已运行、已发布、目标网络可用和用户已使用分别报告。不要用绿色测试或静态清单给个人驾驶/入境资格背书。

## 命令与证据

运行`npm run validate`和`npm run gaps`检查结构与缺口；运行构建和`npm run check`检查发布目录。它们不能验证法规时效或任意自定义模块，新增业务逻辑要补针对性测试。

需要检验本Skill是否真正迁移能力时，给独立Agent仅Skill与场景输入，不提供期望答案；要求实际产物和命令结果，再由评审核对。现成演练输入见 [跨场景验收](../../evals/scenarios.md)，评审标准与输入分开。
