# 旅行网站全流程工坊

把一次旅行做成能真正使用、持续更新的产品。适用于个人、朋友、家庭与商务旅行，不绑定国家、天数、交通方式、视觉风格或托管商。

## 先判定工作模式

- **从零开发**：先读当前资料与目标，走下方全流程。
- **接管已有网站**：先确认正在看的网址、分支、提交及数据版本，再改。先保留已有有效功能。
- **明确小改**：只读取受影响模块的规范，直接改、验证、交付，不重开定位访谈。
- **方向反复或审美不满**：停下叠加补丁，列出已确认约束，用同一真实内容做少量有实质差异的隔离对照。
- **多任务并行**：用户要求或已授权时执行工作树调度。左侧可见任务与内部评审子代理不是同一种交付。

## 开工只补真正缺失的信息

读取当前项目的 travel.md、设计说明、数据、代码和待集成状态。确认：

1. 去哪里、何时、几人、何种旅行，哪些预订已经被用户确认。
2. 谁会在什么设备、网络和语言环境使用，是否必须国内无代理访问或微信打开。
3. 用户要计划整理、视觉样稿、本地可运行产品，还是正式发布。
4. 已有素材、品牌方向、必须保留或明确不要的功能，以及现有操作授权。

用户已经回答的内容不重复追问。已确认事项优先于旧资料；不能把设计偏好当成旅行事实。陌生术语首次给中文含义与英文名。

## 产物与唯一事实来源

沿用项目目录。没有现成结构时，可用：

- travel.md：当前结论、决定、缺口、版本及产物入口。
- 资料/：原件，保持原貌，不直接发布。
- 设计/DESIGN.md：当前生效的设计与交互约束。
- 制作/：网页源码、构建与公开数据。
- 交付/：经过检查的发布目录和说明。

目录有实际内容才建立。结构化字段按现有项目适配，不强建一套 Schema 或知识本体。工作版事实、公开快照和本机状态的边界见[数据与跨国适配](references/data-and-countries.md)。

## 主流程

| 阶段 | 要完成的事 | 离开本阶段的证据 |
| --- | --- | --- |
| 1 事实底稿 | 归并原件、用户确认与官方核验，隔离私人资料 | 时间/地点/预订关系可追溯，冲突有采用依据 |
| 2 产品结构 | 明确首页与地图/日程/交通/清单等适用页面及导航 | 能描述每个入口点击后显示什么、返回哪里 |
| 3 视觉方向 | 用真实数据和目标设备确认字体、图像、密度、动效 | 一组已采用约束；淘汰方案不混入正式页面 |
| 4 垂直样本 | 打通一个完整任务，如“某天活动→购票→地图→返回” | 用户能实际操作，不只是截图 |
| 5 模块制作 | 按适用功能完成状态、异常与素材 | 模块行为证据及可审阅增量 |
| 6 集成 | 主任务检查接受状态、数据、共享样式和资源清单 | 集成版本明确，功能没有被覆盖 |
| 7 双端与网络 | 手机、桌面、触摸/鼠标、目标网络分别验证 | 可复现的尺寸/状态/动作/结果 |
| 8 发布与回读 | 同一网址部署，再检查资源和受影响行为 | 指定提交部署成功，正式网址真实呈现新结果 |

详细操作与用户提示词见[完整 SOP 与精炼提示词](references/sop-and-prompts.md)。不要把八阶段当重复审批流程；已经明确的阶段直接推进。

## 完成标准

- 核心任务确实能完成；字段、图像、按钮和动画不冒充真实业务结果。
- 旅行事实与公开范围正确，必要功能没有为了美观被删。
- 看的是明确版本；模块预览、主分支、本地成品、正式部署分别报告。
- 地图、日程、交通、清单只实现当前旅行适用项。没有租车就不造租车模块。
- 手机和桌面共用内容，布局可以不同。用户要独立页面时，不把长页锚点冒充页面切换。
- 用户指定的风格优先；本案例的手写字体、杉叶、古道与喜剧跳伞都不是默认要求。
- 不因 Skill 使用而扩大外发、账户授权、购买、发布或安装范围。

## 可运行发布核对

项目有发布文件哈希清单时：

~~~sh
python3 <skill-dir>/scripts/audit_release.py <public-dir> --manifest <manifest.json>
~~~

它检查声明文件、内容哈希、目录边界和高置信度敏感字段，**不证明**视觉、业务、网络或自由文本隐私已通过。适配器说明见发布参考。

最终回复只写：已完成什么、实际入口、未验证的关键项、下一步动作。不要逐条播报每次小提交，不要在“准备检查”时宣称已验证。
