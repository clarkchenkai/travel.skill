# 模块 0→1 功能契约

每个模块用同一条验收链：**真实输入 → 默认呈现 → 用户动作 → 状态变化 → 异常/返回 → 持久化边界 → 手机/桌面 → 发布回读**。

下面是功能特性（Feature）清单，不要求每趟旅行全部出现。未适用写原因；不能用空壳、静态文案或假订单凑功能。最终开关、文案与视觉以项目决定为准。

## 1. 标题、首页与入口

**输入**：旅行名称、日期范围、受众、视觉方向、是否需要开场。标题信息可以简洁，日期人数不必在首页重复铺陈。

| Feature | 0→1 实现细节 | 行为验收 |
| --- | --- | --- |
| 网站名 | 初始 HTML title、运行后 document.title、分享标题保持一致；必要时补 og:title/description/image | 初次加载、加载结束、复制/分享卡片分别核对；不承诺微信一定刷新旧缓存 |
| 第一屏 | 首次可见状态完整，不以需要 JS 才能显示的空白背景起步 | 冷缓存、慢网、图片失败时仍能理解如何进入 |
| 入口手势 | 普通点击或有意义的划动；手势阈值、回弹、鼠标/键盘替代清楚 | 短划不误触，纵向滚动不误启动；可键盘完成 |
| 场景状态机 | 写清阶段、可见图层、时序、暂停、完成事件；只一个控制源 | 关键帧符合最新顺序，没有闪帧、断层或无意空场 |
| 跳过 | 若开场明显延迟任务，提供用户认可的跳过方式；可全屏点击，不一定要画按钮 | flight/descent 等进行中可跳；旧回调不拉回；覆盖层被移除 |
| 终态 | 标题和导航按用户约定出现；返回首页是否重播有明确决定 | 返回保持终态或明确重播，不能随机重置 |
| 缺省与降级 | 图片/渲染引擎失败时保留静态场景或直接内容入口 | 无 WebGL、减少动态效果、页面隐藏恢复均不锁死 |
| 首页导航复用 | 首页终态可复用主导航，避免两套图标状态漂移 | DOM 中只有预期数量的菜单，没重叠、没挡点击 |

叙事不是全球固定模板。若用户只要实用路书，不强加启动动画、滑动仪式或虚构人物。

## 2. 页面与导航

**输入**：适用页面清单、默认目的地、首页行为、深链接、手机/桌面布局。

| Feature | 0→1 实现细节 | 行为验收 |
| --- | --- | --- |
| 页面切换 | 采用 hash、路由或服务端页面均可；用户要独立页面时只显示目标板块 | 进入地图后向下滚动不会出现日程/交通/清单 |
| 单一导航 | 同一组页面 ID、标签、图标与选中状态 | 点击、浏览器前进后退、深链接结果一致 |
| 纯图标 | 只有在用户选择且意义足够清楚时去可见文字；保留 aria-label | 读屏名称正确，键盘焦点清楚，图标不会装错背景 |
| 图标素材 | 单图与精灵图分清；透明汽车不能继承地图精灵背景 | 检查实际 computed background/image 及截图，不只看类名 |
| 重复点击 | 当前页面入口可回章首，或保持位置，按项目约定 | 不发生 hash 未改变导致按钮无响应 |
| 页面状态 | 内容保持挂载或显式保存，避免切页丢展开项/选择卡 | 日程→地图→日程仍有原状态，清单记录不清空 |
| 底部安全区 | 底栏留出内容空间，处理设备安全区和软键盘 | 最后一项可以完整看见/点击；输入不会被菜单遮住 |
| 桌面 | 允许悬浮底栏、侧栏等已选方案；内容用宽度重排 | 不复制另一套路由；触摸桌面与键盘仍可用 |

删除顶部栏时同时处理占位、滚动偏移和依赖节点。可以暂保留隐藏节点避免初始化崩溃，但要说明技术债；“视觉隐藏”不能用于隐藏私人数据。

## 3. 路线总览与地点目录

**输入**：主要城市、实际路线顺序、地点 IDs、首次实际到访日期、地图提供商。

| Feature | 0→1 实现细节 | 行为验收 |
| --- | --- | --- |
| 总览 | 精确地理图或艺术行程插画由用户选择 | 不把变形插画当精确距离或导航依据 |
| 地图图像 | 标题/地名可来自生成图，但准确导航数据独立存在 | 目视检查拼字、方向、重复标签与误导连线 |
| 地点目录 | 目录不只放大城市；需要用到的车站、酒店、景点可直接找 | 当前适用地点都能打开，数量以数据为准 |
| 月日 | 按实际到访关联；“确认明天去机场”不是当日到访机场 | 多次到访按“首次/全部”规则明确展示，不从随意字符串猜 |
| 展开方式 | 默认开/关、单列/多列由信息量与用户决定 | 改小字体不会把触控区也缩成不可点 |
| 图片查看 | 只有确实需要时才加放大；整屏已足够时不要再加重复入口 | 保留需要的原图查看方式，关闭原位返回 |
| 网络替代 | 总览可本地静态显示，地点服务可单独失败 | 地图服务不可用不拖垮整个路书 |

## 4. 地点地图弹层

**输入**：当地原名、地址、坐标或明确地图目标、公开联系电话、来源、分享范围。

- 打开时同步标题、当地名、地址、地图 URL、复制内容与来源；防止上个地点残留。
- iframe 的 load 事件可能对应错误页，不能把它等同于地图显示成功。关闭与地址复制必须独立于网络加载。
- 复制保留原文地址，网页反馈“已复制”须对应成功；失败保留可选取文本。
- 地图外跳、复制、来源链接视觉同属一个动作体系。按任务密度决定一行一个还是并排，长当地名/长官方标题要检查。
- 关闭按钮应一次生效。先释放当前弹层、解锁和恢复阅读位置，再按既定历史策略清理状态；避免把关闭完全寄托于跨域 iframe 的后退事件。
- 重复点击关闭不能继续后退到别的页面；ESC、遮罩和浏览器返回要与按钮一致。
- 重新打开从合理起点开始，旧网络回调不改新地点状态；关闭后中止无用加载。
- 是否使用 Google Maps 由地区可访问性决定；可选择其他合法可用服务，原名/地址/坐标不跟提供商绑定。
- 桌面弹层有阅读上限，手机弹层能滚动并保留关闭入口。不能用 CSS 高度锁住大字号用户。

**最短验收**：从长日程滚到中段 → 打开地点 → 关闭一次 → 原日与原展开项仍在 → 切另一地点 → 地址与目标同步 → 模拟网络失败仍可关闭/复制/外跳。

## 5. 每日日程

**输入**：日期、标题、活动、真实时段、固定出发时刻、关联住宿/交通/票务/来源。

| Feature | 0→1 实现细节 | 行为验收 |
| --- | --- | --- |
| 完整日期 | 生成全部天数；日期线与当地日期按实际旅行规则处理 | 没有漏天、重复天、跨日挪错活动 |
| 日摘要 | 日期 + 简洁标题；其他状态只按用户需要出现 | 不把日序/日期/路线/人数反复铺一遍 |
| 展开控件 | 可见的加减/箭头或其他明确方式 | 图片再亮也能看见；点击区域不随图标细线缩小 |
| 活动排序 | 时间可精确，也可“上午/抵达后”；明确二者 | 不把建议分钟冒充固定班次 |
| 时间版式 | 长时间段可完整读出；不要塞进过窄侧栏 | 07:15–08:25、次日00:30、当地语言长文本不乱行 |
| 简介与细节 | 默认只显示行动摘要，原详细信息与地图按需查看 | 精简的是初始密度，已有有用事实没有丢失 |
| 日封面 | 对应实际国家/城市/氛围，六天不必六个雷同高塔 | AI 意象不新增游览安排；标题仍反映真实转场 |
| 票务 | 相关购票状态出现在对应事件，不重复计同一票 | 已购/撤回/跨天共享按相同 ticketId 联动 |
| 日末收起 | 长日程可在底部收起并定位摘要 | 收起后焦点和滚动位置合理 |
| 状态保存 | 切页、关弹层、换屏宽度不重置用户操作 | 状态稳定，记录范围准确 |
| 动画 | 只对有意义的出现/展开做一次反馈 | 避免父容器与子项双 opacity 动画造成住宿闪现 |
| 桌面 | 可双列日卡，打开跨列/主从布局；正文限制行长 | 不把46个活动机械摊成小方卡；数据数量不变 |

天气、季节、营业与路线关闭信息需要当前官方核验；艺术封面不能当景色、道路或天气实证。

## 6. 航班与跨境段

**输入**：完整飞行旅程与航段，机场 IATA、当地名称、航站楼、出发/到达时间及时区、已订状态、提示。

- 一张卡表达一趟完整旅程；中转保留每航段和停留时长。直飞不造中转。没有订票证据时，卡片与示例数据都不能默认“已确认/已出票”。
- 首要信息是城市/机场、日期、起降时刻与时区；航班号/航站楼容易定位。
- 航班号（如XY123）不是电子票号、PNR或预订确认码。公开票卡不默认显示后者；不能为了“像真登机牌”新造或带入私人凭证。
- 卡片可以有 AI 票纸、撕口与风景票根；**事实、金额、时刻、状态和倒计时用 DOM**。
- 倒计时以绝对时间计算，跨时区/夏令时/跨日不直接减钟面；过期不出负数，也不伪装实时航班状态。
- 下一趟航班可默认选中。所有飞行完成后保留回看，不自动删路书。
- 横滑、往返按钮、分页点、卡数、aria-current同步。容器隐藏时不把当前卡算成第0张；重新显示和改宽度后恢复。
- 卡内长备注可以改变自身高度，不拉伸票纸纹理或裁切相邻卡；不因更新高度形成 ResizeObserver 循环。
- 当用户取消折叠，删掉外层 details/summary 和相应 toggle/open 依赖；不能只让它默认 open 仍留下无用控制。
- 用户选择统一参考时区时同时转换日期/时刻/标签，原始值不改，能恢复各地时间。
- 去程与返程提示各自对应真实活动。取消冗余“已确认出票”说明不等于删票据状态数据。
- 已有往返机票时，不因“收尾”又添加一个重复返程图文模块。

**最短验收**：默认下一趟 → 横滑返程 → 改显示时区 → 展开/收起备注 → 切页回来 → 跨起飞边界计时正确；大字号和小屏不裁切。

## 7. 地面交通与自驾（按适用项）

| 子模块 | 必需内容 | 真实操作与失败边界 |
| --- | --- | --- |
| 铁路 | 站名、班次/购票方式、座位要求、站内换乘、票种区别 | 查票务指引、复制当地名、打开车站地图；未核验班次不固定分钟 |
| 巴士 | 上下车站、方向、支付、预约/排队要求、运行日 | 出发当天能找到运营方信息；断网有关键文字 |
| 步行/徒步 | 路段、距离/时间依据、出入口、补给与天气限制 | 与实际交通和住宿衔接；难度描述有来源 |
| 船/缆车/跨境 | 码头/入口、截止登乘、运行限制、证件要求 | 时区/取消/天气敏感项显式核验 |
| 租车 | 品牌/车型或同级、取还地点、截止、费用币种、燃油/里程、保障 | 订单原名保留；截止倒计时单独算；缺资格不编造 |
| 驾驶 | 行驶方向、证件/翻译、道路/收费/停车、还车检查 | 从当前目的地官方/供应商核验，不搬日本经验 |

需要租车/租赁时，按[25项租赁检查](coverage-and-rental.md)核对产品替代条件、计价/支付、保障、取还、截止与相关状态；不适用时不生成空模块。

页签切换保留各自已展开项。键盘左右/Home/End与可见选中状态一致。票务、时间提示、地图与官方来源不是摆设，至少实操一条完整路径。

## 8. 购票、预约与费用

**输入**：产品名称、适用活动、建议/必须预约区别、在哪里买、当地展示语、价格币种、状态来源。

- 个人勾选与供应商确认分开；勾选不声称出票系统已核验。
- 同 ticketId 多处出现要同步；删除摘要“待购数”不破坏实际票项操作。
- 日文或其他当地语言大字展示/复制只是一种工具，不代表购买已完成。
- 日期、适用范围、人数、年龄、参考票价与实付分清；可选票不被视觉做成必买。
- 费用未知留空或标待确认，不用0元；用 ISO 币种避免相同货币符号误导。
- 纸质背景和提醒图仍以文字可读为先；不把红色纹理误用成危险告警。
- 外链保持真实语义和目标。购买、付款或改变预订依用户当时授权与工具要求执行。

## 9. 住宿与餐饮

住宿按实际入住日关联；午夜入住、连续多晚与退房日分清。公开名称和地址能打开地图；当地原名、入口、到店要求和电话按需要折叠。

- 用户不需要“已订”标签可去掉显示，但保留事实。
- 去掉重复地图名时改为清晰“地图”动作，保留可访问的完整名称。
- 默认不补酒店照片。用户明确要时，说明真实照片/AI意象区别，不能把虚构大厅当酒店实际入口。
- 已有明确接站取消决定，不再次生成“联系酒店接站”的待办。
- 餐厅候选、推荐、已预约、已付款分别表达；不因为看到了餐厅图片就写“已预订”。

## 10. 清单与备忘

**输入**：预设待办/物品、用户新增项、稳定ID、本机状态保存范围。

| Feature | 0→1 细节 | 验收 |
| --- | --- | --- |
| 分类 | 全部/待办/物品或项目适用分组 | 分类及计数定义一致，不机械照搬三个名称 |
| 输入 | 空白/重复/最大长度/中文输入法状态 | 选字回车不误提交，提示有用，焦点可继续输入 |
| 勾选 | 真正改变状态与计数 | 新增、勾选、取消、刷新都一致 |
| 删除/撤销 | 保存原分类与勾选；删除后焦点落在合理下一项 | 跨分类撤销恢复原项，不丢完成记录 |
| 本机存储 | 稳定键与ID；损坏旧数据合理降级 | 不为了测试清空用户浏览器，存储失败如实提示 |
| 横滑分类 | 仅用户需要时实现；阈值、方向锁、多指、边界、误点抑制 | 竖滑和输入不被拦，短滑不切换；模拟事件不算真机实测 |
| 键盘 | 分类左右/Home/End，操作控件可聚焦 | 无鼠标也能完成基本任务 |
| 小巧思 | 背包填充、轻反馈等可探索 | 必须用户采用后才发布；不能把探索提交混进正式版 |
| 资料说明 | 原文来源可查，正文尺度一致 | 页尾不过小、不割裂成突兀底色，链接不丢 |
| 桌面 | 可双列但保持阅读/键盘顺序 | 不把状态分成两份，不自动变成协同系统 |

## 11. 全站交付检查

名称一致；每页只有应有内容；所有字号实际跟随已选字体；图片没有404、精灵串图或错裁；主题/语言切换不改旅行事实；没有遗留展示按钮、占位文本或被否决方案；浏览器记录范围、访问条件和来源边界准确。

无法验证的功能明确写“未测/未完成”。功能存在、单元测试通过、模块预览可用、主页面可用、正式发布、真机微信访问，是不同的证据层级。
