# 构建、发布、访问与持续更新

## 发布前

确认当前目标：本地可运行、预览分享、正式上线，还是开放源码。授权范围沿会话保留，但不从“整理旅行”自动推断注册、购买或公开发布。

选择托管前问清实际访问者与网络。如果同行人在国内无代理、微信内打开，这不是上线后才考虑的附加项。

## Git 与受控输出

1. 在合适项目建仓/复用仓库，先排除原件、凭据、私人JSON和不需要公开的工作记录。
2. 生成公开快照。私人工作数据不能进入CI；源仓库私有也不保护最终公开网站。
3. 构建只输出明确允许的HTML、JS、CSS、公开JSON、图像和许可。
4. 干净检出能构建；依赖版本与运行时可复现。不要依赖本机某个绝对路径或没入Git的文件。
5. 新素材/桌面CSS/字体许可必须进入输出清单；被删素材退出输出。清理目标应只限生成目录，不误删原始图或用户资料。
6. 开源模板另走干净示例数据和历史审计；不把真实旅行仓库一键改public。许可和素材来源独立核对。

GitHub→Cloudflare是本次已跑通的组合，不是所有地区最佳默认。具体配置依据当时官方文档。当前参考入口：
- [Cloudflare Pages Git integration](https://developers.cloudflare.com/pages/get-started/git-integration/)
- [Cloudflare China Network FAQ](https://developers.cloudflare.com/china-network/faq/)

## 主线发布

~~~text
采用需求 → 集成提交 → 干净构建 → 发布清单 → 推送远端
→ 对应提交部署成功 → 原网址版本/资源回读 → 受影响交互
~~~

- 生产使用明确的受控分支；工作树探索不要自动覆盖正式站。
- 首次账号连接/应用安装按工具要求在实际授权步骤处理；展示具体账号/仓库与权限，不默认授权所有仓库。
- 如果部署任务先推过配置提交，主任务整合时保留祖先关系。不要用强推掩盖分叉。
- 同一网址持续更新，用户旧链接仍可用。需要更换域名时说明状态存储的迁移边界。

## 缓存与版本

HTML入口、样式、脚本、数据及新增图片都可能各自缓存。版本查询参数或内容哈希可用，选择一种项目能维护的方法。

检查：
- 页面实际拿到的title/版本。
- 变化资源的HTTP状态与SHA-256或内容标识。
- 网络请求是否加载新资源，而不是404后显示旧占位。
- CDN缓存、浏览器缓存、service worker与工作树旧预览分开诊断。

初次发布可全清单核验；之后检查差异资源即可。每改一行都重新下载整套8MB字体没有价值。源码与构建产物的哈希不同正常，比较相同构建流程的产物。

## 可运行发布审计脚本

~~~sh
python3 <skill-dir>/scripts/audit_release.py ./public --manifest ./release-manifest.json
~~~

manifest使用“相对路径→SHA-256”对象，兼容本项目发布文件校验.json。构建完成后可用下面的标准库代码生成清单，输出位置必须在公开目录外；生成清单不等于审阅通过：

~~~python
from pathlib import Path
import hashlib, json
root = Path('public')
manifest = {p.relative_to(root).as_posix(): hashlib.sha256(p.read_bytes()).hexdigest()
            for p in sorted(root.rglob('*')) if p.is_file()}
Path('release-manifest.json').write_text(json.dumps(manifest, indent=2) + '\n')
~~~

脚本只读，不改目录、不上传、不调用网络：

- 拒绝绝对路径、父目录逃逸和输出目录外的符号链接。
- 检查声明文件存在、哈希匹配及未声明的额外文件。
- 拒绝常见凭证文件/源码仓库残留。
- 检查JSON中明确的private/restricted或高置信度敏感键，以及常见密钥标记。

**返回0只代表这些静态检查通过**。脚本不检查自由文本中的身份/订单、不解读图片、不验证网页运行、不确认许可、不证明国内或微信可访问。字段约定不同要人工核对，不能把“没有命中”当隐私保证。

## 地区、国内与微信

一次访问结果要写清：日期、URL、地区/运营商、Wi-Fi或移动网络、是否代理、浏览器/微信、首屏与地图是否分别可用。

- 本机代理成功不证明国内无代理可用；HTTP200不证明图片/字体/地图都可用。
- 托管可访问与第三方地图可访问是两条链路。正文/图片可用时Google地图仍可能不可用。
- 某服务“不支持中国网络产品”或“没有境内节点”的文档，不能单凭一句话外推为所有大陆用户一定必须VPN。也不能因偶尔可直连就保证稳定。
- DNS、TLS、HTTP、资源和交互分层定位；不要为了测试擅自关闭系统代理或改变用户网络。
- 自定义域名可能改善某些问题，但不自动保证直连。国内可用性要求应通过目标网络实测与合适托管方案解决。
- 没有目标环境就报告未测，并给用户最短实测动作；不要造探测节点或截图。
- 微信里分享卡片可能缓存旧标题/图，页面本身更新不等于卡片刷新；区分两者。

国内访问的最短用户验收：关闭其自愿关闭的VPN → 移动网络打开正式URL → 等待首屏/正文 → 打开一个地图 → 记录失败在哪一层。网站要长期稳定面向该网络时，再选择域名、托管与地图供应商。

## 访问期限与长期维护

网站未设置到期策略，不等于平台永久保证。账号、项目、域名续费、托管政策、访问权限与数据保存各自有生命周期。行程日期结束只影响计划状态/倒计时，不应自动删除路书，除非用户明确要求。

旅行后可保留只读纪念版或按用户要求移除敏感行程。不要默认替用户归档、删除或公开更多内容。

本次回读：

## 无 Git 的已授权发布

用户不允许建仓时，不强行初始化Git。先生成同样受控的静态产物；若用户明确要发布且平台支持直接上传：检查当前官方上传能力→选择已有账号/项目→只上传公开目录或ZIP→记录产物哈希与部署版本→打开正式网址验证。后续更新仍从同一数据/源码构建并发布到同一项目；人工上传的回退版本要能找到。没有可用上传能力或登录授权时，停在实际阻塞步骤并说明，不能把本地ZIP当已经上线。

## 恢复与回退演练

保留Git历史或旧ZIP只说明有恢复材料，不等于已经验证可恢复。重大数据/存储变更或发布风险值得时，在隔离环境或已授权范围演练：

1. 选一个确认可用的提交及对应产物，记录当前生产版本和目标版本。
2. 保全用户操作状态；检查旧代码能否读取当前状态/数据结构，必要时先设计兼容或迁移，不清空状态掩盖问题。
3. 通过可追溯的恢复提交或托管平台的实际回退能力恢复，避免重写共享历史。直接上传项目使用已核对的旧产物。
4. 回读原网址、变化资源、核心入口和个人记录，确认旧版本确实可用。
5. 记录如何重新回到新版本；演练结束恢复约定环境。

没有执行演练写“恢复流程已准备，未演练”。不能承诺供应商自动回滚、所有数据库迁移可逆或跨设备记录不会丢失。
