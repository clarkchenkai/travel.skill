# 动态扩展的交付契约

LLM按用户任务生成代码，不要求用户先设计字段或页面。先区分数据修改、主题变体、业务模块和全新站点，再选最轻路径。

## 模板与页面

- 列出现有页面能承载什么；新页面要说明哪项任务在旧结构中无法顺畅完成。
- 新增页面接入路由、导航、标题、翻译、返回、刷新与直接链接。离开再回来不能丢掉仍需要的展开和操作状态。
- 允许增加或移除页面；不以原模板五页为硬约束。没有航班、租车或酒店的旅行可以省略对应功能。
- 新代码、样式、语言包和静态资源进入该模板的manifest及服务工作线程缓存。不要复制整个私有工作目录作发布包。
- 与母模板的差异记录在一次清楚的提交中。给出恢复路径；有个人状态时保留ID和存储命名空间。

## 业务模块

| 模块例子 | 同时需要处理的关系 |
| --- | --- |
| 租车/露营车 | 资格与使用区域、取还门店/时刻、日程、地图、提醒、交接和供应商政策 |
| 商务/会议 | 固定会面、到场缓冲、私有联系人、公司/个人费用、凭证状态与政策 |
| 家庭/无障碍 | 实际年龄/体能/设备、房型与交通容量、休息、分组和交接 |
| 交通中转 | 绝对时刻、终点当地时间、行李、跨站/机场移动、截止和替代路线 |
| 共同清单/分账 | 谁可读写、状态归属、币种、冲突和离线恢复；localStorage不冒充同步 |

## 最小验收

选一条真实任务从入口走到底；再改变一个权威字段，检查每个引用页面。检查空值、长文本、无效时刻、失效链接、无网络、刷新和返回。只对适用场景测试，不为简单行程造完整后台。

自定义主题名可通过校验，但必须有实际CSS；自定义JSON字段不会自动创建UI。通过模板fork、代码实现和测试来交付，不用“可扩展”三个字替代可运行产物。

生成的本地状态模块需额外检查：localStorage解析出null/数组时安全回退；存储错误提示不能在重绘时消失；操作后若重绘按钮，按稳定ID恢复焦点并避免页面跳动。
