# 可复制的AI设计协作提示词

**以下模板由工作空间根据原文方法编写，不是作者逐字提示词。** 方括号填当前材料。只取当前阶段需要的一段；不要每次机械跑完全部流程。输出放入已有设计说明，不额外制造重复维护文档。

## 重新定义问题

```text
阅读[产品目标、真实内容、现有页面、用户反馈]。
先说用户在什么场景要完成什么，哪里与界面不匹配。
把约束分为用户已确认、代码/内容事实、你的推断、待核实；说明新增反馈改变了哪些约束。
字体、布局、工作流程和业务状态一起考虑。
明确错误直接修，相关的小摩擦放在一起处理。
不要从“更突出”“加按钮”直接推导方案，也不要把第一版实现当不可更换的基线。
```

## 生成真正不同的方案

```text
基于同一组硬约束，为[页面或交互]提出3–4种真正不同的解决办法。
保持已确认的功能与创意；改变叙事、操作顺序、层级、密度或交互模型，不要只换颜色。
用真实长度的数据，在隔离设计稿或HTML中并排展示。
每种写核心假设、保留了什么、牺牲了什么、最可能在哪种真实使用状态失败。
推荐一版并解释；已有授权时继续实现，不把比较变成额外审批。
```

## 将图片和创意交给AI

```text
参考[截图/图片/原型]，具体借鉴[层级/节奏/转场/材料/状态关系]；不照搬[品牌资产/无关结构]。
目标情绪是[用户明确的体验]，主要任务是[实际操作]。
为摄影/插画、功能图标、地图及UI文本分配不同载体：文本保持可读可选，真实地图不能被想象地形替代。
若用AI生图，明确素材用途和构图，生成后视觉检查并接入页面；不把概念稿当运行结果。
比较图片、交互与真实内容共同出现时的效果，避免只评价一张漂亮海报。
```

## 逐元素删减

```text
逐项查看这版设计中的文案、线条、图标、边框、容器、按钮、提示和动效。
每项回答它服务的约束、移除后的具体损失，以及是否与别处重复。
给出一个删减对照并实际展示。
保留能表达任务、状态或用户明确叙事目标的丰富体验；不要把“删减”等同于朴素无趣。
也不要拿补充说明遮掩结构混乱。
```

## 组件与动效工坊

```text
把[组件]先做进隔离showcase，用真实数据跑默认、展开、长文、完成、失败和中断状态。
视图、行为与业务数据分离；复用相同控制，不为每个模块重做一套按钮。
每个动画写触发、起态、路径、终态、重播和中断规则；解释它怎样帮助理解，而不只是宣布用了某个库。
技术按作用选择：例如React管理状态、Three.js负责3D场景、SVG表达线路、浏览器动画负责展开。
这些是本任务的实现选择，不是原文要求。
让关键操作在动画中仍可达；提供减少动态效果与图形能力不足时的替代。
```

## 真实数据预览与回读

```text
用当前真实[日期、路线、标题、价格、状态、长备注]替代示例，保留未知信息。
在已有授权的隔离环境提供可运行预览，说明本地/分享/正式发布分别处于什么状态。
让评审者走完[核心任务]，观察内容、触控、焦点、滚动位置和错误分支。
逻辑测试与视觉使用验证分别记录；不要用测试通过代替设计可用。
发现方向不对可以返工，不因为AI严格执行了提示就认定任务已完成。
```

## 给出能改善品味的批评

```text
先记录你看见/操作时的真实反应，再指向造成这种反应的具体视觉或行为。
按“现象→对用户任务的影响→候选改法→比较方式”给反馈。
找出一个值得保留的做法、一个最像模板的做法、一个操作上费力的地方。
重新比较，不把某个人的喜好包装成普遍规律，不无限增加规则或审查轮数。
```

## 原文与本地模板的区别

原文仅给出少量局部提示例子、方法性动作和工具/团队案例。上述完整prompt、动画状态表、图像来源区分、减少动态效果、组件中断和项目授权处理是本工作空间的可执行补充，分别服务当次任务；不得回写成原作者的逐字说法。
